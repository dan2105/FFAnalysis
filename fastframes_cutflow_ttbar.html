O que é um cutflow?

Um cutflow rastreia quantos eventos sobrevivem a cada corte de seleção aplicado sequencialmente. É uma das primeiras coisas que se verifica ao validar uma análise: cada linha do cutflow mostra a eficiência de um critério e como a composição da amostra evolui conforme os cortes são apertados.

Abordagem no FastFrames

No FastFrames não existe um bloco "cutflow" nativo da mesma forma que em ferramentas como AnalysisTop. Existem duas maneiras complementares de implementar um cutflow:

  1. Via regiões cumulativas — cria-se uma Region para cada etapa, adicionando um corte a mais a cada nova região. O histograma de event count em cada região forma o cutflow.
  2. Via bloco cutflows — o FastFrames aceita um bloco explícito de cutflows no YAML que automatiza essa construção (disponível em versões mais recentes).
ℹ
Seleção-alvo deste tutorial: canal e+jets do ttbar inclusivo — exatamente 1 elétron tight, exatamente 4 jets bons, pT do jet líder > 50 GeV, pT do elétron > 40 GeV.

Passo 1 — Definir as variáveis

Antes de criar as regiões, declare todas as variáveis cinemáticas que deseja monitorar ao longo do cutflow. No bloco Variables do config principal: 

# config_ttbar.yaml

Variables:
  # Multiplicidades
  - Name: nElectrons
    Definition: "nElectrons_tight_NOSYS"
    Title: "Number of tight electrons"
    Binning: [0, 1, 2, 3, 4, 5]

  - Name: nJets
    Definition: "nJets_good_NOSYS"
    Title: "Number of good jets"
    Binning: [0, 1, 2, 3, 4, 5, 6]

  # Cinemática dos jets
  - Name: jet1_pt
    Definition: "jet_pt_NOSYS[0] / 1000."
    Title: "Leading jet p_{T} [GeV]"
    Binning: {Edges: [25, 50, 75, 100, 150, 200, 300]}

  - Name: jet2_pt
    Definition: "jet_pt_NOSYS[1] / 1000."
    Title: "Sub-leading jet p_{T} [GeV]"
    Binning: {Edges: [25, 50, 75, 100, 150, 200]}

  # Cinemática do elétron
  - Name: el_pt
    Definition: "el_pt_NOSYS[0] / 1000."
    Title: "Electron p_{T} [GeV]"
    Binning: {Edges: [25, 40, 60, 80, 120, 200]}

  - Name: el_eta
    Definition: "el_eta_NOSYS[0]"
    Title: "Electron #eta"
    Binning: {Edges: [-2.5, -2.0, -1.0, 0, 1.0, 2.0, 2.5]}
⚠
As variáveis jet_pt_NOSYS[0] requerem que o jet líder exista. Certifique-se de que a seleção da região já garante nJets_good_NOSYS >= 1 antes de acessar o índice 0. Use nJets_good_NOSYS >= 2 antes de [1], e assim por diante.

Passo 2 — Criar regiões cumulativas

Cada região no FastFrames é definida com uma seleção booleana (Selection). Para montar um cutflow, cria-se uma região por etapa, acumulando os cortes anteriores em cada nova região.

✓
Convenção de nomenclatura: use nomes do tipo CF_Pass_X_Pass_Y (CF = CutFlow) para identificar facilmente a sequência de cortes ao abrir o ROOT file. 
Regions:

  # ── Etapa 1: exatamente 1 elétron tight ──────────────
  - Name:      CF_Pass_Ne
    Selection: "nElectrons_tight_NOSYS == 1"
    Variables:
      - nElectrons
      - nJets
      - el_pt
      - el_eta

  # ── Etapa 2: + exatamente 4 jets bons ────────────────
  - Name:      CF_Pass_Ne_Pass_Nj
    Selection: "nElectrons_tight_NOSYS == 1 && nJets_good_NOSYS == 4"
    Variables:
      - nElectrons
      - nJets
      - jet1_pt
      - jet2_pt
      - el_pt
      - el_eta

  # ── Etapa 3: + pT(j1) > 50 GeV ──────────────────────
  - Name:      CF_Pass_Ne_Pass_Nj_Pass_j1pt
    Selection: "nElectrons_tight_NOSYS == 1 &&
                nJets_good_NOSYS == 4 &&
                jet_pt_NOSYS[0]/1000. > 50"
    Variables:
      - nElectrons
      - nJets
      - jet1_pt
      - jet2_pt
      - el_pt
      - el_eta

  # ── Etapa 4: + pT(e) > 40 GeV  (seleção final) ──────
  - Name:      CF_Pass_Ne_Pass_Nj_Pass_j1pt_Pass_ept
    Selection: "nElectrons_tight_NOSYS == 1 &&
                nJets_good_NOSYS == 4 &&
                jet_pt_NOSYS[0]/1000. > 50 &&
                el_pt_NOSYS[0]/1000. > 40"
    Variables:
      - nElectrons
      - nJets
      - jet1_pt
      - jet2_pt
      - el_pt
      - el_eta

Passo 3 — Bloco cutflows (alternativa compacta)

Em versões mais recentes do FastFrames, é possível usar o bloco dedicado cutflows no YAML. Ele gera automaticamente as regiões cumulativas sem precisar repeti-las manualmente: 

cutflows:
  - name:   "ejets_ttbar"
    cuts:
      - name:      "Pass_Ne"
        selection: "nElectrons_tight_NOSYS == 1"
      - name:      "Pass_Nj"
        selection: "nJets_good_NOSYS == 4"
      - name:      "Pass_j1pt"
        selection: "jet_pt_NOSYS[0]/1000. > 50"
      - name:      "Pass_ept"
        selection: "el_pt_NOSYS[0]/1000. > 40"
    variables:
      - nElectrons
      - nJets
      - jet1_pt
      - jet2_pt
      - el_pt
      - el_eta
ℹ
O bloco cutflows cria internamente regiões com nomes como ejets_ttbar_Pass_Ne, ejets_ttbar_Pass_Ne_Pass_Nj, etc. — exatamente o que foi feito manualmente no Passo 2. Prefira esta forma quando a lista de cortes for longa.

Config YAML completo (método de regiões)

# ─────────────────────────────────────────────────────────
# config_ttbar_cutflow.yaml
# Cutflow e+jets para ttbar inclusivo — FastFrames
# ─────────────────────────────────────────────────────────

General:
  OutputDir:     "output_cutflow"
  Lumi:          140.1
  NominalOnly:   true   # para cutflow inicial sem systs

Samples:
  - Name:   "ttbar"
    Type:   "MC"
    DSIDs:  [410470, 410471]
    Weight: "weight_mc_NOSYS * weight_pileup_NOSYS"

Variables:
  - Name: nElectrons
    Definition: "nElectrons_tight_NOSYS"
    Title: "N tight electrons"
    Binning: [0,1,2,3,4,5]

  - Name: nJets
    Definition: "nJets_good_NOSYS"
    Title: "N good jets"
    Binning: [0,1,2,3,4,5,6]

  - Name: jet1_pt
    Definition: "jet_pt_NOSYS[0] / 1000."
    Title: "Leading jet p_{T} [GeV]"
    Binning: {Edges: [25,50,75,100,150,200,300]}

  - Name: jet2_pt
    Definition: "jet_pt_NOSYS[1] / 1000."
    Title: "Sub-leading jet p_{T} [GeV]"
    Binning: {Edges: [25,50,75,100,150,200]}

  - Name: el_pt
    Definition: "el_pt_NOSYS[0] / 1000."
    Title: "Electron p_{T} [GeV]"
    Binning: {Edges: [25,40,60,80,120,200]}

  - Name: el_eta
    Definition: "el_eta_NOSYS[0]"
    Title: "Electron #eta"
    Binning: {Edges: [-2.5,-2.0,-1.0,0,1.0,2.0,2.5]}

Regions:
  - Name:      CF_Pass_Ne
    Selection: "nElectrons_tight_NOSYS == 1"
    Variables: [nElectrons, nJets, el_pt, el_eta]

  - Name:      CF_Pass_Ne_Pass_Nj
    Selection: "nElectrons_tight_NOSYS == 1 && nJets_good_NOSYS == 4"
    Variables: [nElectrons, nJets, jet1_pt, jet2_pt, el_pt, el_eta]

  - Name:      CF_Pass_Ne_Pass_Nj_Pass_j1pt
    Selection: "nElectrons_tight_NOSYS == 1 && nJets_good_NOSYS == 4 && jet_pt_NOSYS[0]/1000. > 50"
    Variables: [nElectrons, nJets, jet1_pt, jet2_pt, el_pt, el_eta]

  - Name:      CF_Pass_Ne_Pass_Nj_Pass_j1pt_Pass_ept
    Selection: "nElectrons_tight_NOSYS == 1 && nJets_good_NOSYS == 4 && jet_pt_NOSYS[0]/1000. > 50 && el_pt_NOSYS[0]/1000. > 40"
    Variables: [nElectrons, nJets, jet1_pt, jet2_pt, el_pt, el_eta]

Lendo o output ROOT

Após rodar o FastFrames, o arquivo output_cutflow/histograms.root conterá uma pasta por região. Para visualizar o cutflow no ROOT interativo: 

// No ROOT prompt ou em um macro
TFile *f = TFile::Open("output_cutflow/histograms.root");
f->ls();

// Conta total de eventos ponderados em cada região
auto getYield = [&](TString region, TString var) {
  TH1D *h = (TH1D*) f->Get(region + "/" + var + "_ttbar_nominal");
  return h ? h->Integral() : 0.;
};

cout << "Pass_Ne       : " << getYield("CF_Pass_Ne",                              "nElectrons") << endl;
cout << "Pass_Ne+Nj    : " << getYield("CF_Pass_Ne_Pass_Nj",                      "nElectrons") << endl;
cout << "Pass_Ne+Nj+j1 : " << getYield("CF_Pass_Ne_Pass_Nj_Pass_j1pt",           "nElectrons") << endl;
cout << "Pass_all      : " << getYield("CF_Pass_Ne_Pass_Nj_Pass_j1pt_Pass_ept", "nElectrons") << endl;

Dicas práticas

1

Rode com NominalOnly: true primeiro

Cutflows geralmente são feitos sem sistemáticos. Definir NominalOnly: true no bloco General reduz drasticamente o tempo de processamento e é suficiente para validar a seleção de eventos.

2

Guarde a região de seleção final com outro nome

A última região do cutflow (CF_Pass_Ne_Pass_Nj_Pass_j1pt_Pass_ept) pode ser simplesmente renomeada para ejets_signal quando a seleção estiver finalizada — evita manter dois blocos idênticos no config.

3

Use NOSYS nas seleções

A string _NOSYS no nome da branch refere-se ao valor nominal, sem variação sistemática aplicada. Sempre use isso nas strings de Selection para garantir que o corte seja aplicado ao valor nominal, mesmo quando rodar com sistemáticos.

4

Adicione uma região "all events" como ponto zero

Para ter a contagem total antes de qualquer corte, crie uma região sem seleção: 

  - Name:      CF_AllEvents
    Selection: "1"   # sem corte
    Variables: [nElectrons, nJets]
5

Múltiplos cutflows no mesmo config

Nada impede de ter cutflows paralelos para outros canais (μ+jets, dilepton) no mesmo arquivo YAML — basta adicionar mais regiões com prefixos distintos, como CF_mu_Pass_Ne, CF_ll_Pass_mll, etc.

Referência de parâmetros YAML

Campo Bloco Tipo Descrição
Name Region string Identificador único da região. Aparece como pasta no ROOT file.
Selection Region string (expressão C++) Filtro booleano aplicado evento a evento via RDataFrame. Suporta operadores &&, ||, comparações, índices de vetores.
Variables Region lista de strings Nomes das variáveis (definidas no bloco Variables global) a serem histogramadas nesta região.
Definition Variable string (expressão C++) Expressão ROOT que calcula a variável. Pode referenciar branches do TTree diretamente.
Binning Variable lista ou mapa Define os bins do histograma. Pode ser lista de bordas (Edges) ou vetor uniforme [min, max, n].
NominalOnly General bool Se true, processa somente a variação nominal — recomendado para cutflows rápidos.
